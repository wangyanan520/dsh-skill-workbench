## 3. 发版链路（0.3.4 已按序执行完毕，下次发版可照抄）

### 3.1 让人登录（唯一需要人的一步）

## 6. 最容易踩的七个坑

1. **E404 不是「包不存在」**：`npm publish` 对无权限 token 返回 E404 而非 401。判断凭据用 `npm whoami`，别用 publish 的报错猜。
2. **默认 registry 是 npmmirror**：任何 `npm login/publish/view` 都要显式 `--registry=https://registry.npmjs.org`。
3. **跨层 scope 必须带括号**：`test(host+tooling): ...` 合法；`test+tooling: ...` 会被 commitlint 判成 type/subject 为空（headerPattern 不匹配）。
4. **`git ls-remote` 会间歇 `Empty reply from server`**（代理抖动）。push 后用 API 复核：`curl -s https://api.github.com/repos/wangyanan520/dsh-skill-workbench/commits/main`。
5. **顺序**：publish → 重建索引 → tag → Release。`build-market-index.mjs` 读的是 registry 的 `dist-tags.latest`，提前跑会把旧版本写进索引。
6. **E403 带 2FA 字样 ≠ token 过期**：publish 返回 `403 ... Two-factor authentication or granular access token with bypass 2fa enabled is required` 是账号安全策略，跟「token 失效的 401/E404」是两回事。`npm login` 得来的会话 token 不带 bypass 2FA 权限，用它在开了 2FA 的账号上发版必被拦。解法：用 npmjs.com 生成勾选 **bypass 2FA** 的 granular token，或发布时加 `--otp=<6 位码>`。合法 token 可以用 `--//registry.npmjs.org/:_authToken=<token>` 临时代入，不必写进 `~/.npmrc`。
7. **publish 的 `202` 不是「已发布」**：registry 接受后返回 `http fetch PUT 202`（异步处理），npm CLI 立刻打印 `+ pkg@ver` 但 `npm view` 仍可能是旧版本。判据是 `curl -o /dev/null -w '%{http_code}' https://registry.npmjs.org/<pkg>/<ver>` 返回 200，以及绕缓存读 `?write=true` 的 `dist-tags.latest` 已更新。别在这之前就 tag，也别急着重复 publish。

提交信息规范见 `docs/GIT-CONVENTIONS.md`（type 白名单、scope 白名单 `client/host/ui/i18n/tooling/test/docs/market/release/deps`、标题按显示宽度 ≤72、中文占 2 列）。
