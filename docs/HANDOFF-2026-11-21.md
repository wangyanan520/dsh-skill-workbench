## 2. 这次修了什么（0.4.0 → 0.4.1）

`package.json` 的 `icon` 从 base64 data URI 改为 `assets/icon.svg`。

- 根因在 DSH 的包元信息校验（`@deepseek-ai/dsh-app-boot` 的 `package-meta.ts`，`iconOf()`）：`icon` 只要匹配 `/^[A-Za-z][A-Za-z\d+.-]*:/u` 就按「带 scheme」拒绝，data URI 正好命中，于是抛出 `<manifestPath>: icon must be a relative file path`；相对路径还要求 resolve 后 `realpath` 留在 manifest 目录内、扩展名为 SVG/PNG/JPEG/WebP、是常规文件且 ≤256 KiB。
- 旧值把 528 B 的 `assets/icon.svg` 内联成 data URI，资产本身没问题、也在 `files` 白名单里，只是元信息格式不被接受。
- 修复只改 `package.json` 一行（`2e18f66`），不复制根目录图标、不动 `market/index.json`（市场索引里的 data URI 是索引格式，与包元信息无关）。
- 安装副本同步：桌面 profile 的 `node_modules/dsh-skill-workbench/package.json` 曾手工改成 `assets/icon.svg`；本次正式发版后用 pnpm 重装到 0.4.1，不再依赖手工修补。

## 6. 本次踩坑

1. **icon 只接受相对文件路径**：data URI 被 `/^[A-Za-z][A-Za-z\d+.-]*:/u` 判成带 scheme 的地址；不是大小、格式或 `files` 的问题，别去改资产或 `files`。
2. **commitlint 的 scope 白名单没有 build/meta**：`fix(build): ...` 能过 pre-commit，但 commit-msg 报 `未知 scope：build`。`build` 是合法 type，不是合法 scope；`package.json` 清单类改动用无 scope 的 `fix:`（或表内 scope）。
3. **pnpm 的 minimumReleaseAge 会拦住刚发布的版本**：`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` 不是网络或凭据错误，是 supply-chain 策略（24 小时）。单次 `--config.minimumReleaseAge=0` 可绕过；不要改 profile 的长期策略。
4. **npm registry 传播有延迟**：publish 返回 `+ dsh-skill-workbench@0.4.1` 不等于 `dist-tags.latest` 立刻可见，本次约 80 秒；期间 `npm view` 可能报 0.4.0。`build-market-index.mjs` 必须等 `latest` 真的切到新版本后再跑，否则会生成旧索引。
5. **换磁盘不等于换内存**：桌面端必须完全重启才加载新插件；重启前「设置 → 插件」的版本来自已加载的包，不会因 `node_modules` 变化而更新。当前会话跑在宿主里，重启这一步只能由人做。
6. **dshmarket 的 24 小时安全等待期**（#1252）与 CLI 安装无关：日志 `still inside the safety wait (dsh-skill-workbench@0.4.1 until 2026-11-22T07:13:24.185Z) — updates are held`，在市场点更新会被 `PROFILE_RELEASE_BLOCKED`，别误判成装坏；同一时刻市场对 dshmarket 自身的更新失败（lockfile 同名行 #883）与本插件无关。
7. **`gh` 仍未登录**：Release 用 keychain 里的 GitHub token 走 API（`user_status=200`、`TOKEN_LEN=40`），与 0.3.5 相同。
8. **工作区遗留 4 个未提交文件**：`docs/VERIFY.md`、`test/menu-live-test.mjs`、`test/render-page-test.mjs`、`test/test-extra.mjs` 属于之前会话的真机验证记录，本次没有混入任何发布 commit。
