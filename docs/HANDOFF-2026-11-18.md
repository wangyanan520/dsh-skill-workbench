## 2. 这次修了什么

`host/routes.js` 的挂载守卫从「全局布尔 + 已存在就跳过」改成「后挂载者接管」：

- 旧实现：`globalThis[Symbol.for('dsh-skill-workbench.mounted')]` 为真时新 apply 直接 return，不注册任何 effect；旧 fiber 的 disposer 稍后执行，又删掉 symbol 与路由。
- 后果：HMR 重载（插件热更新、市场覆盖安装）后新实例没有路由，旧实例又把旧路由带走，表现为 `/api/dsh-skill-workbench/*` 全 404、侧栏「技能管理」消失，看起来像「更新后插件坏了」。
- 新实现：新 apply 在 effect 里先调用上一实例的 `dispose()` 卸掉旧注册，再注册自己的；每个实例持有独立 `token`，disposer 只在 `globalThis[MOUNT_SYMBOL]?.token === token` 时执行，迟到的旧 cleanup 不会误删新挂载。
- 测试：`host/selftest.mjs` 的 `applyHostPlugin` 用例改为接管语义，`makeFakeContext().webServer.register` 现在记录 `released` 路由，断言接管时旧实例 17 条路由被释放、旧 cleanup 不影响新实例、全部清理后可重新挂载。

## 3. 桌面端 0.3.3 → 0.3.4 更新失败的根因（与本次修复相关但独立）

现象：2026-11-18T12:22Z 在 dshmarket 里批量更新，`billion-context`、`dsh-better-sidebar`、`dsh-cost-meter`、`dsh-skill-workbench` 连续 4 个报「这个插件正在使用中，桌面端不允许现在移除」（`bundle-in-use`），同一批 `@michengai/*` 7 个成功。

证据与机制：

- 每次失败只花 0.18–0.46 秒，远快于成功项的 1.2–6 秒，说明**没走到 pnpm 卸载**，是在 HMR 重载阶段被拒。
- 市场日志原文：`the desktop app removed its bundle row before refusing the update (bundle-in-use) — restored it so the plugin still loads on the next boot (#935)`。`selectBundle` 写盘成功，问题在随后的 `reload()`/`recompose`。
- 宿主 `removeBundle` 的守卫：`selectBundle(name,false)` 后，只要该 bundle patch 的任一 row 仍有 `fiber.uid != null` 的 entry，就抛 `bundle-in-use`。
- 对照实验：对**无关插件** `dsh-cost-meter` 执行 `plugin_manager set_bundle(enabled=false)`，同样返回 `application:"restart-required"`、`restartReason:"package-moved"`，route 仍 200。说明当前进程里任何 bundle 的移除都做不了，**与 dsh-skill-workbench 的代码无关**。
- 根因：`recompose` 调 `publish` 时，`ResolutionRouter.replace` 发现 profile 包的 `realDir` 与新 resolution 的包目录不一致（pnpm 重装/换目录），抛 `ResolutionRestartRequired("package-moved")`，`recompose` 提前 return，`entry.update` 没执行、旧 entry 仍挂载，紧随其后的守卫命中；市场 #935 再把 bundle 行恢复，所以磁盘不会坏。

规避：**完全退出 DSH（⌘Q，确认 `pgrep -f "DeepSeek Harness"` 为空）再重开**，然后在市场点更新。这是宿主返回的 `nextStep` 本身的要求，不是绕过。重启后进程按磁盘重建解析，`package-moved` 不再成立。详细记录见 `docs/03-known-issues.md`。

## 6. 本次踩坑

1. **npm 401 ≠ 网络问题**：`~/.npmrc` 有 token 但已过期，`whoami` 直接 `401 Unauthorized`；profile 的 `.npmrc` 里没有可用 npmjs token。先 `npm login`，别急着排查代理。
2. **git push 报 `Empty reply from server`**：当前网络对 GitHub 的 HTTP/2 不稳，`git -c http.version=HTTP/1.1 push origin main` 一次成功；`ls-remote` 一直正常，所以别误判成凭据问题。
3. **市场 #935 的恢复行为**：更新被 `bundle-in-use` 拒后，市场会把 bundle 行写回 `dsh.profile.bundles`，避免插件下次启动消失；因此失败后磁盘仍是旧版本、可以直接重试，不需要手工修 manifest。
4. **日志位置**：`/Users/wyn/.dsh/profiles/desktop/.dsh-market/log.ndjson`；宿主自身的 HMR 警告只落主进程 stdout，`~/Library/Logs/DeepSeek Harness/` 里没有可用的运行日志。
5. **`gh` 未登录**（本机 `gh auth status` 显示未登录），但 keychain 里的 GitHub token 带 `repo` scope，可用 §4 的 API 方式建 Release。
